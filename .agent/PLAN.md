### 5.1 D-009：Agent 能否处置 dependabot 自动 PR —— ✅ **已授权批次处置（2026-10-03 人类裁决）**

- **裁决结果：** ✅ **授权**按 D-005 先例执行批次处置（批次 commit + 关闭 9 个 PR + 留言关联）；❌ **仍禁止**逐个合并 dependabot 自动 PR。
- **裁决前的核实事实：** STATE 多轮记录「自动 PR 不碰」，构成事实禁令；而 T-037（D-005 先例）恰恰是**关闭**这批 PR 而非合并，方向一致。真正的问题是「**该由谁触发这次处置**」——禁令导致它 5 天无人认领。
- **支撑证据：** 9 个 PR 全部只改 `package.json` + `pnpm-lock.yaml` **同两个文件**，逐个合并需 9 次串行 rebase；#109 已证明逐个合并会先合入无用的 #107 再失败。
- **执行载体：** Issue **#165**（blocked by #164）。
- **约束（裁决同时确立）：** 批次处置**必须**在 #164 落地 `main` 之后执行；**不得**用 `--admin` 单独 merge 任何 dependabot PR。
- **长期影响（新事实）：** 依赖 PR **静置超过一周即应视为需处置的信号**——因为 dependabot 每周一 09:00 扫描，额度被占满则该次扫描作废。
- **重新评估触发：** 出现高危 CVE 且因限流无法上报；或用户要求改为每周自动合并（属 CI 改造，须另立调查单）。

### 5.2 D-010：`@cloudflare/vite-plugin` 浮动如何治理 —— ✅ **Planner 自主裁定（非用户决定）**

- **问题：** vite-plugin 一周连发 6 版并把 `wrangler` peer 下限逐版抬高，而 adapter 始终声明浮动 `^1.53.0`（本轮实测 `14.3.2`/`14.3.3`/`latest` 声明完全相同）。「只抬 wrangler pin」是否仍是可接受的做法？
- **裁定：** ❌ 不是。改为**成对不变量**：用 `pnpm-workspace.yaml` 的**有界 override 锁定 vite-plugin 解析**，`wrangler` 精确 pin 跟随其 peer下限（今日 = `4.147.0`）。两者必须同 commit 移动。
- **为何不升级为用户决策：** ① 可逆（删 override 即恢复原状）；② 不引入新产品取向；③ 与已生效的 D-003（wrangler 精确 pin）、D-007（override 必须有界）同源，只是把它们应用到被依赖方；④ 不做的后果是 #165 每次刷新 lock 都可能把 `main` 构建成红。
- **执行载体：** Issue **#164**（含「反向证据」验收，区分「真堵住」与「碰巧没浮」）。
- **重新评估触发（已写明于 DECISIONS.md）**：上游 adapter 改为精确依赖 vite-plugin，或 vite-plugin 改为宽 peer，或锁定版本出现安全公告。
