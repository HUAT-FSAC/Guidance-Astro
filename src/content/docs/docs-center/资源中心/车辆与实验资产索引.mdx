## 资产分类与责任人

| 类别 | 车队实际资产 | 维护责任 | 使用前必须确认 |
| --- | --- | --- | --- |
| 车辆 | 无人驾驶方程式赛车、测试底盘、遥控/接管设备 | 机械负责人 + 安全负责人 | 车辆状态、急停、轮胎和当前改动 |
| 传感器 | 摄像头、激光雷达、IMU/GNSS 及支架线束 | 感知/电气负责人 | 型号、安装位姿、标定和时间同步 |
| 计算与网络 | 工控机、车载网络、交换机、供电模块 | 电气/算法负责人 | 镜像、驱动、IP/接口和剩余磁盘 |
| 数据与地图 | 采集包、标注集、地图、回放结果 | 算法负责人 | 数据来源、坐标系、版本和授权 |
| 设计与制造 | CAD、STEP、BOM、原理图、线束图 | 机械/电气负责人 | 适用车辆、版本和是否可制造 |
| 软件与配置 | 代码、启动文件、参数、容器或镜像 | 对应模块负责人 | 提交 SHA、依赖和回滚版本 |

## 车辆与硬件索引字段

每台车辆或关键设备建立一条索引记录。编号可以按车队已有规则替换，示例只说明字段形状。

| 字段 | 示例 |
| --- | --- |
| 资产编号 | CAR-TEST-01 / LIDAR-01 |
| 状态 | active / repair / reserved / retired |
| 当前版本 | 底盘改动号、传感器标定版本或软件 SHA |
| 所在位置 | 实验室、车库、测试场地或借用人 |
| 责任人 | 日常维护人和测试日值班人 |
| 最近点检 | 日期、点检人、异常和处理链接 |
| 关联文件 | CAD、原理图、标定文件、日志或 GitHub Issue |

## 借用与归还流程

1. **借用前**：在索引中确认状态为 active，登记借用人、用途、计划归还时间和测试任务。
2. **装车前**：拍摄安装状态，核对接口、供电、固定件和标定文件，任何改动都写入任务卡片。
3. **测试后**：导出原始日志，恢复或标注配置变化，检查外观、接插件、磁盘空间和电量。
4. **归还时**：更新状态、位置、最后一次点检日期；若有异常，标记 repair 并关联 Issue，不把故障设备留在 active。

## 数据和软件版本规则

- 数据目录至少包含采集日期、车辆编号、场景、传感器配置和操作者。
- 地图、标定和参数必须写明坐标系、适用车辆和生成代码版本。
- 交付测试记录时同时保存软件仓库、分支、提交 SHA 和启动配置。
- 过期资产移动到归档区，并在索引中保留弃用原因和替代版本。
- 不在公开 Issue、日志截图或文档中提交密钥、内网密码和个人敏感信息。
