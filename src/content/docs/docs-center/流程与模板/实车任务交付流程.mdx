<Aside type="tip" title="一张任务卡片贯穿全流程">
仿真、台架和实车任务都使用同一张任务卡片。每次测试只改变输入版本、车辆配置和结果，不另起一套口头流程。
</Aside>

## 适用范围

这套流程适用于传感器标定、感知/定位/规控参数调整、线束或底盘改动，以及会影响实车行为的代码和配置变更。纯文字修订可以走轻量 Review，但涉及车辆安全或控制输出时必须补充实车验收记录。

## 标准交付路径

| 阶段 | 必做动作 | 进入下一阶段的证据 |
| --- | --- | --- |
| 1. 提出问题 | 写清现象、影响范围、目标和优先级 | 任务卡片有负责人和截止时间 |
| 2. 方案评审 | 明确改动点、依赖、回滚方式和安全风险 | 评审结论为通过或有条件通过 |
| 3. 实现与自测 | 在仿真或台架先验证，记录命令和结果 | 代码/配置、测试日志和变更说明齐全 |
| 4. 实车前检查 | 核对车辆、硬件、软件 SHA、场地和急停 | 安全负责人签字或在任务卡片确认 |
| 5. 受控实车测试 | 小范围、低风险开始，逐项完成测试用例 | 原始日志、视频和异常时间点已保存 |
| 6. 验收与归档 | 对照目标指标判断通过、回滚或继续修复 | 验收结论、Issue/PR 和资产版本可追溯 |
| 7. 复盘 | 记录有效做法、失败原因和后续行动 | 行动项有负责人和截止日期 |

## 实车前检查清单

- [ ] 变更已经过模块负责人 Review，且能说明回滚版本
- [ ] 车辆编号、传感器配置、工控机和供电状态已记录
- [ ] 场地、天气、测试边界和观察员已确认
- [ ] 急停、遥控/驾驶接管和通信链路已点检
- [ ] 日志录制、时间同步和数据盘空间已确认
- [ ] 测试用例按低速、短距离、单变量顺序排列

## 验收门槛

| 结果 | 使用条件 | 后续动作 |
| --- | --- | --- |
| 通过 | 目标行为和安全约束均满足，日志可复核 | 合并变更，更新版本索引并归档 |
| 有条件通过 | 功能可用但有不影响当前测试的已知问题 | 建立后续 Issue，标明限制和责任人 |
| 回滚 | 出现安全风险、不可解释的控制异常或数据损坏 | 恢复上一个稳定版本，保留失败证据并复盘 |
| 继续修复 | 未达到指标但可安全复现 | 补充最小复现，回到方案评审阶段 |

## 交付包最小内容

交付时不要只提交代码或一张结果截图。最小交付包应包含：变更说明、版本信息、测试命令/场景、原始日志位置、结果对比、已知限制、回滚方法和对应 Issue/PR。
