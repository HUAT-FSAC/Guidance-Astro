## 首周目标

新成员在第一周不以“看完所有资料”为目标，而是完成一次可追踪的小任务：找到负责人、完成环境验证、参加一次评审，并把运行记录归档。这样下一位成员可以复现你的结果。

## 0—30 分钟：确认身份和边界

| 检查项 | 完成标准 | 输出 |
| --- | --- | --- |
| 车队账号 | 能访问 GitHub 组织、共享资料和沟通频道 | 账号与权限清单 |
| 角色方向 | 与部门负责人确认算法、电气、机械或项管方向 | 负责人姓名与联系渠道 |
| 当前赛季 | 能找到 2025 赛季入口和对应模块文档 | 一条入口链接 |
| 安全边界 | 知道急停位置、测试区域、当班安全负责人 | 安全培训确认 |

## 第一次工作会话

按照下面顺序完成一次最小闭环，优先选择仿真、台架或资料整理任务；实车任务必须由模块负责人安排。

1. **拉取并确认版本**：记录仓库、分支、提交 SHA 和依赖版本，不直接在主分支上试验。
2. **确认输入**：写清车辆编号、传感器/执行器配置、地图或数据集版本，以及本次任务的预期现象。
3. **执行最小测试**：先跑一个可以在 10 分钟内完成的命令或场景，保存终端输出和失败日志。
4. **向负责人汇报**：用“已完成 / 卡点 / 下一步”三行说明同步，不只发送截图。
5. **归档结果**：把运行记录、问题链接和结论放入任务卡片，确保别人能按记录复现。

## 四类角色的首个交付物

| 角色 | 建议首个任务 | 首周交付物 |
| --- | --- | --- |
| 算法 | 复现一条感知、定位或规控基础流程 | 运行命令、输入版本、结果截图和问题清单 |
| 电气 | 阅读电气架构并核对一段线束或原理图 | 架构笔记、接口疑点和安全注意项 |
| 机械 | 阅读总装结构并确认一个待加工或待装配部件 | 结构拆解、尺寸/装配风险和图纸链接 |
| 项管 | 整理一次会议、采购或赛事材料 | 清单、截止日期、负责人和缺口 |

## 首次实车任务的记录字段

在进入测试场地前，任务卡片至少填写以下字段。缺字段时先补齐，不用“先跑起来再说”代替点检。

| 字段 | 示例内容 |
| --- | --- |
| 测试对象 | 车辆编号、测试场地、测试日期 |
| 软件版本 | 仓库、分支、提交 SHA、启动配置 |
| 硬件配置 | 传感器、工控机、供电状态、轮胎/底盘变更 |
| 测试目标 | 要验证的行为、指标或复现条件 |
| 安全责任 | 驾驶/遥控、场地观察、急停和电气负责人 |
| 结果归档 | 数据目录、日志、视频、Issue 或 PR 链接 |

## 首周验收

- [ ] 能找到本部门负责人和车辆测试负责人
- [ ] 能独立完成一次仿真、台架或文档任务并归档
- [ ] 参加过一次方案评审或文档 Review
- [ ] 知道实车测试前的安全点检和测试后的数据归档位置
- [ ] 能用任务卡片说明当前状态、风险和下一步
