<Aside type="caution" title="安全异常先停车">
车辆失控、急停失效、制动/转向异常、动力或高压风险等问题，先停止测试并保护人员，再补充 Issue。反馈记录不能替代现场安全处置。
</Aside>

## 一次测试，一份可复现反馈

现场口头描述要在测试结束前转成 Issue 或任务卡片。最小目标是让没有到场的人，仅凭记录知道“哪台车、哪个版本、什么条件、出现了什么、如何验证修复”。

## 现场记录顺序

1. **保证安全**：停止车辆或切换到安全状态，记录急停/接管是否生效。
2. **冻结现场**：不要立即刷写新版本、覆盖日志或改变硬件；拍摄车辆和仪表状态。
3. **记录版本**：保存车辆编号、软件提交 SHA、配置/地图/标定版本和硬件改动。
4. **标记时间点**：记下测试编号、圈次、场景、速度区间和异常开始/结束时间。
5. **保存证据**：保留原始日志、视频、终端输出和必要的复现数据，不只上传裁剪截图。
6. **建立反馈**：一个可独立处理的问题对应一个 Issue；多个症状有关联时相互链接。

## 优先级与处理动作

| 等级 | 判断标准 | 处理动作 |
| --- | --- | --- |
| P0 | 涉及人员/车辆安全，或无法保证急停、制动、转向、供电安全 | 立即停止相关测试，通知安全负责人和项目负责人，未解除前禁止复测 |
| P1 | 阻塞下一次计划测试或核心功能，已有稳定复现条件 | 纳入最近一次联调，指定负责人和修复验证版本 |
| P2 | 不阻塞当前测试的缺陷、体验问题或文档缺口 | 进入 backlog，补充影响范围和计划处理窗口 |

## 从反馈到关闭

| 状态 | 负责人要补充的内容 |
| --- | --- |
| 新建 | 事实、版本、证据、优先级和影响车辆 |
| 已确认 | 根因假设、复现结果、临时规避方案和负责人 |
| 修复中 | PR/变更链接、目标版本和需要回归的测试用例 |
| 待验证 | 验证车辆、软件/硬件组合、通过标准和计划日期 |
| 已关闭 | 回归日志、结果对比、限制条件和文档/索引更新 |

## 反馈质量检查

- [ ] 标题能在项目看板中被检索到，包含模块或车辆编号
- [ ] 版本和硬件配置足以判断是否与其他问题相同
- [ ] 日志路径可访问，且没有提交密钥、密码或个人敏感信息
- [ ] 期望与实际行为可区分，避免只写“效果不好”
- [ ] 修复后有对应测试用例和回归证据
- [ ] 关闭前更新相关文档、参数或资源索引
