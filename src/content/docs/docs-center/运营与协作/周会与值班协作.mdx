<Aside type="tip" title="把协作安排到测试前">
实车测试日临时找人、临时找车和临时确认版本都会放大风险。周会只要锁定负责人、车辆、场地、版本和验收指标，测试日就按清单执行。
</Aside>

## 固定周节奏

| 节点 | 会议/动作 | 当天必须留下的结果 |
| --- | --- | --- |
| 周初 | 任务分拣与风险同步 | 本周目标、负责人、依赖和阻塞项 |
| 周中 | 算法、电气、机械联调 | 当前软件/硬件版本和待解决问题 |
| 测试日前 | 安全与资源确认 | 测试许可、值班表、车辆和场地 |
| 测试日 | 受控运行与数据采集 | 测试编号、原始数据、异常时间点 |
| 周末/下个工作日 | 结果评审与归档 | 通过/回滚结论、Issue、下一周行动项 |

## 责任人地图

| 角色 | 主要职责 | 必须参与的节点 |
| --- | --- | --- |
| 项目负责人 | 排优先级、协调资源、确认里程碑 | 周初、风险升级、验收 |
| 测试负责人 | 编排用例、确认场地和记录结果 | 测试日前、测试日、结果评审 |
| 安全负责人 | 急停、接管、供电和人员边界确认 | 每次通电和实车运行前 |
| 模块负责人 | 对代码、参数、硬件改动和回滚负责 | 方案评审、联调、验收 |
| 数据/文档管理员 | 维护资产索引、日志和会议记录 | 测试后、版本发布、归档 |

## 实车测试日值班表

测试前至少在群公告或任务卡片中写清以下内容：

    日期 / 场地：
    车辆编号：
    测试负责人：
    安全负责人：
    接管/遥控负责人：
    观察员与记录员：
    软件提交 SHA / 硬件配置：
    测试用例与停止条件：
    数据目录：
    预计结束与归还点检人：

### 测试日交接

- 交班人说明车辆当前状态、已完成圈次、未解决异常和剩余电量/存储空间。
- 接班人复读软件 SHA、硬件改动、测试边界和停止条件，双方在任务卡片确认。
- 任何安全异常先停止运行，再通知项目负责人和安全负责人；不要为了“完成一圈”继续采集。
- 测试结束后由记录员确认原始数据已复制，再允许清理车载临时文件。

## 周会状态更新模板

每个模块用三分钟更新，内容保持可执行：

    本周完成：已合并的 PR、已通过的测试或已归档的资料
    当前风险：会阻塞哪一次联调/实车测试，证据是什么
    下周计划：任务、负责人、完成标准和依赖
    需要协助：需要谁在什么时候做什么决定

## 跨部门交接规则

代码、参数、线束、机械件或标定文件发生变化时，交接信息必须同时包含“变更内容、适用车辆、验证结果、回滚方法和下一位负责人”。只发文件名或口头说“已经改好”不算完成交接。
